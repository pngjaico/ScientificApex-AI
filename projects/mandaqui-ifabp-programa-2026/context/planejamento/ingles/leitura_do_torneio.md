# Interpreting the executable tournament

3 November 2026. The `idea tournament` CLI was run in D: using nine planning candidates. PASS means the required fields were populated, not scientific approval.

The score mixes roles and rewards low risk: postponing the cohort or running a pilot may rank above the doctorate. The code also awards database-availability points for a populated `database_plan`, even when that text states no database exists. I therefore did not use the total as an objective measure of merit, availability or publication probability. The runtime was not changed to force a winner.

**Role-specific decision:** A1/SBO is the conditional first main hypothesis; A2/vascular AMI is the alternative if actual flow supports it; A3/NOMI requires additional infrastructure; A4/leakage needs a new population; A5/broad panel and radiomics is rejected in phase one. S1/paired analytical validity is the master's; S2/CT reliability is the strongest undergraduate project; S3/feasibility is the contingency. N0/postponement is legitimate if gates fail.

All retain `novelty_status: uncertain` and `status: hypothesis-generating`. Automatic `can_be_promoted_to_project: true` does not authorize collection, corpus or analysis; registration, ethics, feasibility and judgment remain mandatory. No hypothesis became a clinical claim in D:.

The subsequent portfolio organizes C01–C30 with P/C/I, timing, dependencies and explicit integration. It expands the programme without turning heuristic scores into evidence.
